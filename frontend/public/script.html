API Pulse — Presentation & Demo Walkthrough Script

A Step-by-Step Speaking Guide for Demoing to Mentors, Leads & Clients

1. The 30-Second Elevator Pitch (Start Your Demo Here)
"Good morning Sir / Team. Today I am excited to present API Pulse."

"In modern software engineering, backend microservices fail silently. Latency spikes, unexpected 500 errors, and broken third-party APIs often go unnoticed until users complain. API Pulse is an intelligent, full-stack API observability and synthetic monitoring platform. It continuously checks endpoint health, tracks response latency percentiles (P50, P95, P99), fires automated alerts before outages affect customers, and uses an integrated AI SRE Copilot to automatically diagnose root causes and suggest code fixes."
2. Page-by-Page Screen Walkthrough

Page 1: Executive Dashboard

Core Goal: High-level telemetry overview showing total system health score, request throughput, and active incidents.
🖥️ Screen Action: Open the Dashboard. Point to the Top Stat Cards, the 24h Request Volume Chart, and the Response Time Distribution.
💬 What to Say: "Here on the Executive Dashboard, engineering managers and DevOps teams get an instant snapshot of the entire API ecosystem. At the top, you see our overall Health Score (95/100), total monitored endpoints (289), active projects, and unresolved alerts. Below, the interactive chart illustrates 24-hour request volume, error distributions (2xx, 4xx, 5xx), and P50 to P99 latency percentiles."
  • Health Score Calculation: Weighted score based on uptime %, success rate, and latency SLA adherence.
  • Visual Charts: Recharts-based responsive graphs tracking live traffic volume and status distributions.

Page 2: Projects Management

Core Goal: Group endpoints logically by microservice, team, or environment.
🖥️ Screen Action: Navigate to Projects. Show the list of microservices: Authentication Service, Payment Gateway, Notification Service.
💬 What to Say: "Next, the Projects page enables enterprise team isolation. Rather than having a messy flat list of APIs, we group endpoints by microservice or service domain. Each project defines its base URL (e.g. https://api.pulse.dev), environment status, and aggregates health telemetry specifically for that service."
  • Service Isolation: Group APIs by domain (Billing, Customer Portal, Core Microservices).
  • Base URL Inheritance: Endpoints dynamically inherit their base URL from the parent project.

Page 3: Endpoints & One-Click OpenAPI / Swagger Import (⭐ Key Feature!)

Core Goal: Instant onboarding of hundreds of endpoints via OpenAPI specs with real-time filtering and status inspection.
🖥️ Screen Action: Open Endpoints page. Click the 'Import APIs' button. Show the modal with OpenAPI JSON/YAML, Raw Text, or URL option.
💬 What to Say: "This is one of our most powerful features: One-Click OpenAPI Specification Import. Developers don't want to type 300 endpoints manually. With API Pulse, you simply upload a Swagger YAML, paste JSON, or supply a live URL. The system automatically parses all routes, methods (GET, POST, PUT, DELETE), path parameters, request bodies, and headers in under 3 seconds. Here we have 289 microservice endpoints fully imported and ready to monitor."
  • Supported Formats: OpenAPI 3.0, Swagger 2.0, Raw JSON, YAML, and live remote spec URLs.
  • Smart Parameter Resolution: Automatically resolves template parameters like {id} to UUIDs.
  • Fast Batch Check: Chunked parallel verification executes 289 endpoint checks in just 6-8 seconds.

Page 4: Monitoring & Automated Synthetic Checks

Core Goal: Background synthetic ping engine that actively verifies availability, SSL/TLS, and SLA thresholds.
🖥️ Screen Action: Go to Monitoring. Highlight the Live Heartbeat, uptime percentage (99.9%), and recent health score transitions.
💬 What to Say: "On the Monitoring page, API Pulse acts as an active synthetic observer. Rather than waiting for real user failures, our background scheduler executes synthetic HTTP requests at configured intervals (e.g., every 30 seconds). It records exact response times, validates response status codes against expected SLAs, and classifies endpoints as Healthy, Degraded, or Down."
  • Background Scheduler: Continuous non-blocking Node.js cron scheduler.
  • SLA Latency Thresholds: Flags endpoints as 'Degraded' if latency exceeds custom SLA limits (>500ms).
  • Automatic Recovery: Detects when a down endpoint recovers and marks prior alerts as resolved.

Page 5: Alerts & Incident Triggering

Core Goal: Rule-based anomaly detection alerting developers via audio, toasts, and in-app notifications before outages escalate.
🖥️ Screen Action: Navigate to Alerts page. Point to an active alert card. Click the top navbar bell icon to reveal the Notification Center.
💬 What to Say: "When an endpoint fails or its latency spikes, the Alerting Engine triggers instantly. It creates an incident ticket, computes severity (Critical, Warning, Info), and immediately dispatches a real-time notification to the top navbar with audio feedback. Developers can acknowledge alerts, review the failure message, and assign them to engineers."
  • Smart Deduplication: Prevents notification storming while allowing manual triggers to notify in real time.
  • Audio Alerts: Sound feedback on Critical, Warning, and Recovery events.
  • Lifecycle Tracking: Active -> Acknowledged -> Resolved state transitions.

Page 6: Testing Playground (Custom API Runner)

Core Goal: Postman-like in-browser API client with automated assertion suites for ad-hoc verification.
🖥️ Screen Action: Open Testing page. Select GET or POST, click 'Send'. Show the live response pill, headers, and assertion results.
💬 What to Say: "The Testing Playground provides a built-in Postman experience right inside the browser. Developers can select any imported endpoint or enter a custom URL, configure headers, query params, and JSON payloads, and click 'Send'. The runner executes the request, measures server latency, parses response headers, and runs automated assertions like status code checks or body contents verification."
  • Live Response Pill: High-contrast status tag (e.g. 200 OK, 400 Bad Request, 500 Internal Error).
  • Assertion Engine: Validates status codes, latency thresholds (<300ms), and JSON path values.

Page 7: Structured Logs & Telemetry

Core Goal: Immutable audit log of every request, response, duration, and error snippet for deep forensics.
🖥️ Screen Action: Navigate to Logs. Click a log row to open the detailed drawer showing raw headers and error traces.
💬 What to Say: "The Logs page serves as our forensic audit trail. Every single health check, playground run, and manual ping is stored with microsecond precision. You can search by endpoint path, filter by status codes (2xx, 4xx, 5xx), and inspect detailed request/response payloads to debug tricky intermittent bugs."
  • Search & Filter: Instant search across methods, paths, and status ranges.
  • Persistent Storage: Dual database drivers supporting fast SQLite and production PostgreSQL.

Page 8: AI Root Cause Analysis (SRE Copilot) (⭐ Showstopper!)

Core Goal: Automated AI diagnostic engine powered by Gemini AI with instant local SRE heuristic fallback.
🖥️ Screen Action: In Endpoints or Alerts, click 'Diagnose with AI'. Show the modal with Technical Title, Causes, and Code Fix snippet.
💬 What to Say: "Finally, this is our marquee capability: AI Root Cause Analysis. When an endpoint experiences an outage, developers usually waste hours digging through server logs. In API Pulse, our SRE Copilot analyzes the telemetry—response code, latency percentiles, error payloads—and generates a production-grade diagnosis with exact probable causes, troubleshooting checklists, and actionable TypeScript / Node.js code snippets fixing the bug."
  • Dual-Tier Architecture: Combines Google Gemini 2.5 Flash with an instant local SRE Heuristic Engine.
  • Circuit Breaker Protected: 15-minute cooldown circuit breaker ensures zero UI lag if API quotas are exhausted.

Q: What happens if Gemini AI quota runs out? "We engineered an automated 15-minute Circuit Breaker that instantly falls back to our internal SRE Heuristic Engine with 0ms latency."
Q: Where is data stored? "In-memory store backed by dual persistence drivers: fast local SQLite for zero-config development, and PostgreSQL for production."
